## Bug Fixes

### BUG-01 — Env-var API Key Redacted Before Storage (P0)

**File:** `src/config/config.ts:79`
**Impact:** HILBRAS_PROVIDER_KEY env var users get HTTP 401

**Root Cause:** `redact(providerKey)` is called before storing in `authentication.apiKey`. The `redact()` function replaces characters with `*`, so the actual key is lost.

**Fix:** Store the raw key, only redact for logging.

```typescript
// BEFORE (line 79):
authentication: { type: "bearer", apiKey: redact(providerKey) },

// AFTER:
authentication: { type: "bearer", apiKey: providerKey },
```

**Verification:** Unit test that `loadConfig()` with `HILBRAS_PROVIDER_KEY` produces a provider with the actual key.

### BUG-02 — ReasoningNormalizer Buffer Leak (P1)

**File:** `src/reasoning/normalizer.ts`
**Impact:** User text misclassified as reasoning across chunks

**Root Cause:** When `feedText()` is called with text that partially matches a reasoning tag, the buffer accumulates across calls. If a tag is detected, `_buffer` is stripped but the content inside is returned even on subsequent calls. The normalizer doesn't reset between different message roles.

**Fix:** Add a `reset()` call at the start of each new message, and only return the *new* content (not the full buffer) when inside a tag.

```typescript
// Add method to track last returned index
private _lastReturnedIndex = 0;

feedText(text: string): ReasoningChunk | null {
  this._buffer += text;

  if (!this._inTag) {
    for (const pat of TAG_PATTERNS) {
      if (pat.test(this._buffer)) {
        this._inTag = true;
        this._buffer = this._buffer.replace(TAG_PATTERNS[0], "");
        this._lastReturnedIndex = this._buffer.length;
        return this._buffer.length > 0
          ? { type: "reasoning", text: this._buffer }
          : null;
      }
    }
    return null;
  }

  if (/<\/(?:thinking|reasoning|reason)>/i.test(this._buffer)) {
    this._inTag = false;
    const cleaned = this._buffer.replace(TAG_PATTERNS[1], "").trim();
    const newText = cleaned.slice(this._lastReturnedIndex).trim();
    this._buffer = "";
    this._lastReturnedIndex = 0;
    return newText ? { type: "reasoning", text: newText } : null;
  }

  // Return only new content since last call
  const newText = this._buffer.slice(this._lastReturnedIndex);
  this._lastReturnedIndex = this._buffer.length;
  return { type: "reasoning", text: newText };
}
```

**Verification:** Unit test that feeds text in chunks and verifies no duplicate content.

### BUG-03 — FetchTransport Double-Release (P2)

**File:** `src/transport/fetch.ts:114-148`
**Impact:** Connection pool count goes negative, blocking all requests

**Root Cause:** `requestFn()` has a `finally` block that calls `this._release(origin)`. The outer `catch` block at line 145 *also* calls `this._release(origin)`. On error, both run.

**Fix:** Remove the release from the outer catch block. The `finally` in `requestFn` always runs.

```typescript
// BEFORE (lines 114-148):
const requestFn = async (): Promise<Response> => {
  try {
    return await fetch(url, { ... });
  } finally {
    this._controllers.delete(controller);
    this._release(origin);  // <-- runs on success AND error
  }
};

try {
  const promise = requestFn();
  // ... coalesce logic ...
  return await promise;
} catch (error) {
  this._release(origin);  // <-- ALSO runs on error → double release!
  throw error;
}

// AFTER:
const requestFn = async (): Promise<Response> => {
  try {
    return await fetch(url, { ... });
  } finally {
    this._controllers.delete(controller);
    this._release(origin);
  }
};

try {
  const promise = requestFn();
  // ... coalesce logic ...
  return await promise;
} catch (error) {
  // release already happened in requestFn's finally block
  throw error;
}
```

**Verification:** Unit test that sends a failing request and verifies pool count stays at 0 (not negative).

### BUG-06 — FetchTransport Interval Never Cleared (P2)

**File:** `src/transport/fetch.ts:42-44`
**Impact:** Memory leak in long-lived processes; interval keeps running after all requests complete

**Root Cause:** `setInterval` is called in the constructor but the interval ID is never stored, so it can't be cleared.

**Fix:** Store the interval ID and provide a `destroy()` method.

```typescript
// Add field:
private _cleanupTimer: ReturnType<typeof setInterval> | null = null;

// In constructor:
if (typeof setInterval !== "undefined") {
  this._cleanupTimer = setInterval(() => this._cleanupPools(), this._idleTimeout);
}

// New method:
destroy(): void {
  if (this._cleanupTimer !== null) {
    clearInterval(this._cleanupTimer);
    this._cleanupTimer = null;
  }
  this.abort();
}
```

**Verification:** Unit test that creates a FetchTransport, calls destroy(), and verifies the interval is cleared.

### BUG-07 — Circuit-Breaker halfOpenCalls Negative (P3)

**File:** `src/reliability/circuit-breaker.ts:92,111`
**Impact:** Cosmetic issue; counter goes negative when multiple failures occur in half_open state

**Root Cause:** `recordFailure()` decrements `_halfOpenCalls` without checking if it's already 0.

**Fix:** Add a guard.

```typescript
// line 92 (recordSuccess):
this._halfOpenCalls = Math.max(0, this._halfOpenCalls - 1);

// line 111 (recordFailure):
this._halfOpenCalls = Math.max(0, this._halfOpenCalls - 1);
```

**Verification:** Unit test that records multiple failures in half_open state and verifies `_halfOpenCalls` stays >= 0.

### BUG-08 — Duplicate RequestId Reported as Budget Error (P3)

**File:** `src/cost/tracker.ts:81`
**Impact:** confusing error message when `reserve()` is called twice with the same ID

**Root Cause:** `reserve()` returns `null` for duplicate IDs. The caller reports this as "budget exceeded" when it's actually a duplicate ID.

**Fix:** Throw a descriptive error instead of returning null.

```typescript
// BEFORE:
if (this._reservations.has(requestId)) return null;

// AFTER:
if (this._reservations.has(requestId)) {
  throw new Error(`Duplicate reservation ID: ${requestId}`);
}
```

**Verification:** Unit test that calls `reserve("req_1", 0.5)` twice and expects the error.

### BUG-09 — extractJson Returns Raw Text (P3)

**File:** `src/output/structured.ts`
**Impact:** When `extractJson()` fails to find valid JSON, it returns the raw input text instead of throwing

// BEFORE:
return fallback ?? input;

if (fallback) return fallback;

## Architecture Fixes

### C5 — SDKConfig Not Consumed by HilbrasClient (P1)

**File:** `src/client/client.ts:99-112`
**Impact:** `SDKConfig` providers list is ignored; env-configured providers never get registered

**Root Cause:** `HilbrasClient` constructor reads `sdkConfig` for policy/budget fields but ignores `sdkConfig.providers`. The `loadConfig()` function returns providers, but they're never passed to `addProvider()`.

**Fix:** In the constructor, if `sdkConfig.providers` is non-empty and no explicit providers were added, register them.

```typescript
// In constructor, after budget setup:
if (sdk?.providers?.length) {
  for (const provider of sdk.providers) {
    // Only add if not already registered
    if (!this._registry.get(provider.name)) {
      this.addProvider(provider);
    }
  }
  if (sdk.defaultProvider && !this._defaultPolicy?.provider) {
    // Set default provider from SDKConfig
  }
}
```

**Verification:** Unit test that creates a client with `sdkConfig` containing providers and verifies they're registered.

## Adapter Fixes

### A3 — Anthropic Adapter Tool Message Translation (P1)

**File:** `src/adapters/anthropic.ts:78-81`
**Impact:** Tool result messages sent as `role:"tool"` (OpenAI format) instead of `role:"user"` (Anthropic format)

**Root Cause:** The Anthropic API doesn't have a `tool` role. Tool results must be sent as `role:"user"` with `tool_result` content blocks.

**Fix:** Transform tool messages in `_buildBody()`:

```typescript
body.messages = nonSystemMessages.map((m) => {
  if (m.role === "tool") {
    return {
      role: "user",
      content: [{
        type: "tool_result",
        tool_use_id: m.toolCallId ?? m.name,
        content: m.content,
      }],
    };
  }
  return { role: m.role, content: m.content };
});
```

**Verification:** Unit test that builds a body with a tool message and verifies it's translated to `role:"user"` with `tool_result`.

## Security Fixes

### SEC-01 — RealtimeSession WebSocket SSRF Bypass (P2)

**File:** `src/realtime/index.ts:49`
**Impact:** Custom `baseUrl` bypasses the SSRF guard entirely

**Root Cause:** `RealtimeSession.connect()` uses `this._config.baseUrl` directly without running it through `validateBaseUrl()`.

**Fix:** Add SSRF validation in the constructor or connect method.

```typescript
import { validateBaseUrl } from "../security/url-guard.js";

async connect(): Promise<void> {
  const baseUrl = this._config.baseUrl ?? this._getBaseUrl();
  
  // Validate custom URLs (built-in URLs are trusted)
  if (this._config.baseUrl) {
    const guard = validateBaseUrl(baseUrl.replace("wss://", "https://"));
    if (!guard.ok) {
      throw new Error(`RealtimeSession URL rejected: ${guard.reason}`);
    }
  }
  // ... rest of connect
}
```

**Verification:** Unit test that creates a RealtimeSession with a private-network URL and expects rejection.

## Reliability Fixes

### R1 — RealtimeSession.connect() Can Hang Forever (P2)

**File:** `src/realtime/index.ts:75-77`
**Impact:** If WebSocket never opens (network issue), `connect()` hangs indefinitely

**Root Cause:** The promise resolution is based on polling `this._connected` with no timeout.

**Fix:** Add a configurable timeout.

```typescript
async connect(timeoutMs = 30_000): Promise<void> {
  // ... WebSocket setup ...

  return new Promise((resolve, reject) => {
    const timeout = setTimeout(() => {
      reject(new Error(`RealtimeSession connection timeout after ${timeoutMs}ms`));
    }, timeoutMs);
    
    const check = setInterval(() => {
      if (this._connected) {
        clearInterval(check);
        clearTimeout(timeout);
        resolve();
      }
    }, 50);
  });
}
```

**Verification:** Unit test that creates a session with a non-connecting URL and verifies timeout.

## Wiring Fixes

### W1 — Telemetry Sinks Not Wired (P1)

**Files:** `src/telemetry/opentelemetry.ts`, `src/telemetry/structured-logger.ts`, `src/telemetry/body-logger.ts`
**Impact:** 4 telemetry modules built/tested/exported but never connected to the client

**Fix:** Add optional `telemetry` config to `HilbrasClientConfig` and wire into the hook system.

```typescript
// In HilbrasClientConfig:
telemetry?: {
  structuredLogger?: StructuredLogger;
  openTelemetry?: OpenTelemetryExporter;
  bodyLogger?: BodyLogger;
};

// In constructor, register hooks:
if (config?.telemetry?.structuredLogger) {
  this._hooks.on("*", (event) => {
    config.telemetry!.structuredLogger!.record(event);
  });
}
```

**Verification:** Unit test that creates a client with telemetry and verifies events are forwarded.
