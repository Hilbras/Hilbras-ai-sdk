## Defects found while building this

Recorded because each one changed the work:

1. **Astro/Remix regression I introduced.** Routing all four chat handlers
   through one `resolveChatFields` gave Astro and Remix the Next.js `true`
   default, so a caller could newly choose the model. Caught by a test asserting
   the factory model wins; fixed by defaulting those adapters to `false`.
2. **`onError` return value is discarded in the streaming path.** `stream.ts`
   types `onError` as `(error) => Response | Promise<Response>` but awaits it
   inside the `ReadableStream` and ignores the result, so a returned response
   never reaches the client. Not fixed here — it is a public API decision. The
   tests document the actual behaviour.
3. **`maxSteps` is not a provider field.** It bounds the client-side tool loop,
   so the clamp is observable only through `streamText`, not the request body.
4. **Equivalent mutant in `forwardedClientIp`.** `if (index < 0) return
   undefined` is unobservable in JavaScript — every negative array index reads
   `undefined`. Verified exhaustively in node over 7 headers × `trustProxy`
   0–11, zero inputs differ. No test written; the guard stays as documentation.

| Defect | Where |

| Angular example imported `useChat` / `ChatService`; the module exports `HilbrasChatService` with signals and `submit()` | Angular |

| `redis.incrWithExpiry` — a method that does not exist on any client | `docs/security.md` store example |

Two were mine: the React section was mislabelled `/react-client` while passing
`api`, a prop only `/react` accepts; and the signing example used
`HilbrasClient` without importing it.

### Guard

`tools/check-doc-examples.sh` extracts every fenced example and typechecks it
against the built package, one file per block, because a reader pastes one
example — not the concatenation of all of them, where duplicate identifiers
mask real errors. Wired into CI and available as `npm run check:docs`.

Two defects in the guard itself, both found by using it:

- It initially collected only `tsx`/`ts`/`typescript`, so the `vue` and
  `svelte` blocks were never checked at all — the two that were broken. It now
  extracts the `<script>` block from component fences.
- A block tagged `ts fragment` is an explicit opt-out for snippets that
  continue an earlier example in the same section. Five in `docs/security.md`
  use it; without the tag they are reported as undefined names.

Coverage: 19 standalone examples checked across both documents, 13 fragments
skipped. Verified non-vacuous — mutating a React block to import `useChat` from
the root makes it fail with `TS2305`.

## Consolidation — complete for SDK surface

Three packages were folded into `@hilbras/sdk`; three were deliberately left
alone. The dividing line is whether the code is **SDK surface** or a
**distributable in its own right**.

| Package | Decision | Why |
|---------|----------|-----|
| `@hilbras/next` | folded → `/nextjs/api`, `/nextjs/edge` | Route handlers and middleware are SDK surface; neither was ever published. |
| `@hilbras/react` | folded → `/react-client` | Hooks are SDK surface; never published. Split from `/react` because both export `useChat` with different transports. |
| `@hilbras/ui` | **kept** | A component library, not SDK surface: 15 components plus a tailwind subpath. |
| `hilbras` (CLI) | **kept** | A `bin` executable with a shebang. |
| `create-hilbras-app` | **kept** | Ships non-code template files: `files: ["dist", "templates"]`. |

Folding the last three would put a scaffolder's templates and a CLI binary
inside the SDK tarball, growing it for every consumer who only imports the SDK.
The owner declined that; recorded so a later session does not re-propose it as
an oversight.

### Harness defect found and fixed

The mutation harnesses detected only `Tests N failed`, missing `Tests no tests`
— which is what a module that cannot be *collected* prints. A stray JSX return
under a tsconfig with no `--jsx` produced exactly that, and the harness reported
a real kill as a hole. Fixed in all four harnesses; 37 mutations killed in total
(10 frameworks, 8 middleware, 15 stream, 4 react-client).
