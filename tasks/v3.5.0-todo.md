## Defects found while building this

Recorded because each one changed the work:

1. **Astro/Remix regression I introduced.** Routing all four chat handlers
   through one `resolveChatFields` gave Astro and Remix the Next.js `true`
   default, so a caller could newly choose the model. Caught by a test asserting
   the factory model wins; fixed by defaulting those adapters to `false`.
2. **`onError` return value is discarded in the streaming path.** `stream.ts`
   types `onError` as `(error) => Response | Promise<Response>` but awaits it
   inside the `ReadableStream` and ignores the result, so a returned response
   never reaches the client. Not fixed here — it is a public API decision. The
   tests document the actual behaviour.
3. **`maxSteps` is not a provider field.** It bounds the client-side tool loop,
   so the clamp is observable only through `streamText`, not the request body.
4. **Equivalent mutant in `forwardedClientIp`.** `if (index < 0) return
   undefined` is unobservable in JavaScript — every negative array index reads
   `undefined`. Verified exhaustively in node over 7 headers × `trustProxy`
   0–11, zero inputs differ. No test written; the guard stays as documentation.

## Deferred to v4.0.0

- [ ] React route-based inference mode (`useChat` / `useCompletion` gain a
      `route` option; `client` becomes conditionally optional — breaking).
      Design note: the hook currently holds a `HilbrasClient` from context and
      calls `client.stream()`; a route mode needs a transport swap at the hook
      boundary, not a change inside the SDK.
- [ ] `trustClientFields` default flips to `false` for the Next.js factories.
- [ ] Signature profile default flips to `v2` (v3.4.0 decision).
