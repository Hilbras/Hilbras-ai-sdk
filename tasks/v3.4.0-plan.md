# Implementation Plan: v3.4.0 Security Enforcement Integrity

## Scope

Implement [`SPEC-v3.4.0-security.md`](../SPEC-v3.4.0-security.md) as an additive
minor release. Do not remove exports, change provider adapters, introduce
runtime dependencies, or lower coverage thresholds.

The single intentional behavior change is a malformed `config.rbac` failing at
client construction. Every other change is an internal fix or is opt-in.

## Dependency order

```text
authorization-contracts
        ↓
authorization-resolver
        ↓
rbac-enforcement
        ↓
client-authorization
        ↓
signing-profiles → replay-guard → transport-integrity
        ↓
compat-docs
        ↓
release-gate
```

## Phase 0 — Baseline characterization

### Task 0.1: Pin current authorization behavior

Characterize the v3.3.0 baseline before changing it:

- `checkPermission` decisions for well-formed roles, including the
  no-restrictions role;
- `createRBACMiddleware` decisions for missing role, unresolvable body, and
  rate-limited role;
- `loadConfig`/resolver handling of a `rbac` block (accepted, unvalidated, no
  effect).

**Acceptance:** the suite passes against v3.3.0 and documents exactly which
observable behaviors must be preserved under `enforcement: "permissive"`.

**Verify:** `npx vitest run tests/security/rbac.test.ts tests/config/`

**Files:** new `tests/security/authorization-baseline.test.ts`.

## Phase 1 — Authorization contracts

### Task 1.1: Add authorization types and diagnostics

- Create `src/security/authorization.ts` with `RBACRole`, `RBACConfig`,
  `RBACRequestContext`, `AuthorizationDecision`, `AuthorizationDiagnostic`,
  `AuthorizationEnforcement`, and `AuthorizationOptions`.
- Extend `RBACRole` with `allowedTools` and `deniedTools`.
- Re-export the new types from `src/security/rbac.ts` and `src/index.ts`.

**Acceptance:** `tsc --noEmit` passes; existing `RBACRole`/`RBACConfig`
annotations still compile; no existing export is removed.

**Verify:** `npx tsc --noEmit`

### Task 1.2: Add policy validation

- Add `validateRbacConfig(config)` returning `ConfigDiagnostic[]` in
  `src/config/config-resolver.ts` (or a colocated validator) covering every
  rule in spec §6, including the `defaultRole` existence check.
- Emit **error** diagnostics so the strict resolver throws at construction.
- Add diagnostics codes: `RBAC_INVALID_ROLES`, `RBAC_INVALID_ROLE`,
  `RBAC_INVALID_RESTRICTION_LIST`, `RBAC_INVALID_NUMERIC_LIMIT`,
  `RBAC_INVALID_RATE_LIMIT`, `RBAC_TOOL_POLICY_CONFLICT`,
  `RBAC_INVALID_ENFORCEMENT`, `RBAC_UNKNOWN_DEFAULT_ROLE`.
- Call it from `validateValues()`.

**Acceptance:** every malformed shape in spec §6 produces a diagnostic and
`resolveConfig({ strict: true })` throws; valid configs produce none.

**Verify:** `npx vitest run tests/config/`

## Phase 2 — Authorization resolver

### Task 2.1: Role resolution

- Implement the default role resolver as `config.defaultRole ?? "default"`.
- Support an injected `resolveRole`, including `null`/`undefined` and unknown
  role names.
- Catch resolver exceptions and convert them to a decision rather than
  propagating (fixes R11).

### Task 2.2: Request-context resolution

- Implement the default `resolveRequest`: resolve the provider from the request
  URL, then read `model`, `max_tokens`, and the tool name from a JSON body.
- Return `null` when the body is not JSON or the provider is unresolvable.
- Support an injected `resolveRequest` for non-SDK traffic.

**Acceptance:** given a request whose URL matches a registered provider base URL
and whose body carries `model`, the decision context is populated and
`checkPermission` is actually invoked (fixes R2).

**Verify:** `npx vitest run tests/security/authorization-resolver.test.ts`

## Phase 3 — RBAC enforcement

### Task 3.1: Rewrite the enforcement path

- Replace the inline logic in `createRBACMiddleware` with a single
  `evaluateAuthorization()` call.
- Apply the permissive/strict table from spec §4.
- Return 403/429 `Response` objects only for `deny` outcomes; `diagnostic`
  outcomes call `onDiagnostic` and continue.

### Task 3.2: Make rate limiting and budget real

- Consume tokens on an allowed decision and key the bucket by
  `rbac:<userId>:<role>` (fixes R3).
- Enforce `maxBudgetPerSession` through the client's budget tracker, or report a
  diagnostic/deny when no tracker is available (fixes R8).

### Task 3.3: Attribute audit events

- Include `userId` and `role` in `rbac_denied` and `rbac_rate_limit` events
  (fixes R9).
- Ensure no secret value appears in any description.

**Acceptance:** the middleware returns 403 for a resolved disallowed
provider/model/tool, 429 once the rate limit is consumed, and stays permissive
for every unresolvable case.

**Verify:** `npx vitest run tests/security/`

## Phase 4 — Client authorization

### Task 4.1: Add `ProviderRegistry.findByUrl`

- Resolve a provider name from a request URL by matching configured base URLs.
- Match on origin and tolerate base-path prefixes and trailing slashes.
- Return `null` for an unknown URL.

### Task 4.2: Wire `config.rbac` into the client

- Compose the authorization middleware ahead of user-supplied middleware when
  `resolvedSdk.rbac` is present.
- Bind provider resolution lazily so `addProvider()` after construction is
  covered.
- Add `getAuthorizationDiagnostics()` returning a redacted, ordered decision log.

### Task 4.3: Enforce the tool policy

- Add a `ToolPolicy` derived from `SDKConfig.allowedTools` / `deniedTools` and
  narrowed per role.
- Apply it before every tool execution in the shared path used by
  `ToolLoopAgent` and by `client.complete()` when tools are supplied.
- Reject a denied tool with an actionable error naming the tool and the policy.

**Acceptance:** a client configured with `rbac` denies an out-of-policy provider,
a disallowed model, and a denied tool; a client without `rbac` behaves exactly as
in v3.3.0.

**Verify:** `npx vitest run tests/security/ tests/config/`

## Phase 5 — Signing profiles and replay protection

### Task 5.1: Add the profile switch

- Add `profile` and `nonceHeader` to `RequestSignerConfig`.
- Freeze `v1` byte-for-byte against the v3.3.0 implementation.
- Pin the existing signer tests to `v1` explicitly.

### Task 5.2: Implement the `v2` profile

- Bind body digest, key id, and nonce into the canonical signing string.
- Emit `x-hilbras-content-digest`; omit it when the body is unreadable.
- Widen the body type to `string | Uint8Array`.
- Rebuild the canonical string in `verify()` from received bytes; never trust a
  received digest header (fixes S1, S2, S7).
- Stop string-coercing `FormData` in `signingMiddleware` (fixes S5).
- Use a correctly named digest header so the `sha512` mismatch is gone (fixes
  S9).
- Add a per-sign nonce so same-second requests differ (fixes S8).

### Task 5.3: Add the replay guard

- Add `ReplayGuard` with a bounded FIFO cache, timestamp window, and skew bound.
- Add `RequestSigner.verifyFresh()` composing verification and the guard.
- Inject `now` for deterministic tests.

**Acceptance:** a modified body fails `v2` verification even when the digest
header is also modified; a replayed signature fails `verifyFresh()`; a signature
outside the window fails with a distinct reason; `v1` output is unchanged.

**Verify:** `npx vitest run tests/security/`

## Phase 6 — Transport integrity

### Task 6.1: Fix middleware composition

- Rewrite `composeMiddlewares` as a recursive compose so downstream stages re-run
  per retry attempt (fixes S4).
- Add tests for a retry stage followed by a signing stage and by an auth stage.

### Task 6.2: Propagate streaming errors

- Check `res.ok` in `MiddlewareTransport.stream` and throw
  `ProviderRequestError` with the status (fixes R10).
- Add a test asserting a 403 on the streaming path is an error, not an empty
  stream.

### Task 6.3: Normalize outgoing headers

- Normalize the header bag to a single lowercase key set before merging signed
  headers (fixes S6).
- Add a test with mixed-case input headers asserting no duplicate keys.

**Acceptance:** `composeMiddlewares(retry, signing)` re-signs per attempt;
`composeMiddlewares(retry, auth)` re-authenticates per attempt; a non-2xx
streaming response throws; signed requests carry one header key per name.

**Verify:** `npx vitest run tests/middleware.test.ts tests/v2.5-structural.test.ts tests/security/`

## Phase 7 — Documentation

### Task 7.1: Document the security model

- Rewrite the authorization and signing sections of `docs/security.md` to match
  enforced behavior, including the permissive default and what it does not
  guarantee.
- Document `ReplayGuard`, `verifyFresh`, and signature profiles.

### Task 7.2: Write the v3.3 migration guide

- `docs/migration-from-v3.3.md` covering the malformed-`rbac` construction error,
  the opt-in `v2` profile, `strict` enforcement, the middleware retry fix, and
  the streaming error propagation change.

### Task 7.3: Update active docs, examples, and the audit

- Update `README.md`, `docs/api-reference.md`, `CHANGELOG.md`, and
  `HILBRAS-SDK-FULL-AUDIT.md` with a v3.4.0 addendum mapping every finding
  R1-R11 and S1-S9 to its fix and test.
- Add `examples/authorization/` demonstrating role resolution, strict
  enforcement, and a client-wired policy.
- Correct any documentation that claims RBAC already enforces per-user roles.

**Acceptance:** no active document claims a control that is not enforced, and
every closed finding cites a test.

## Phase 8 — Release

- Version bump to `3.4.0` across `package.json` and `package-lock.json`.
- Full gates: `npm test`, all CI shards, `npm run test:packages`,
  `npm run pretest`, `npm run lint`, `npm run build`, `npm run check:package`,
  `npx publint`, `npm audit --omit=dev`, `npm run size`, `npm run benchmark`,
  and `npm run test:coverage` with thresholds unchanged.
- Open a PR, wait for Node 22 and Node 24 CI, merge to protected `main`, tag
  `v3.4.0`, create the GitHub release, and publish to npm.
- Verify the published package from a clean install: runtime smoke covering RBAC
  denial, tool-policy denial, `v2` signing, and replay rejection, plus a
  `tsc --strict` type smoke.

## Risk register

| Risk | Mitigation |
|---|---|
| Enforcing RBAC starts returning 403s for operators who set `rbac` expecting it to work | `permissive` default; migration guide; explicit `strict` opt-in |
| Malformed `rbac` now throws at construction | Documented as the single intentional behavior change; actionable diagnostic naming the offending key |
| Rate limits begin returning 429s | Only for roles that declare `rateLimit`, which was previously a no-op; called out in the changelog and migration guide |
| Recursive compose changes retry chain behavior | New tests for re-entry; existing composition and retry tests must stay green |
| Streaming non-2xx now throws instead of yielding an empty stream | Adapters already throw for non-2xx on the non-streaming path, so this aligns the two paths; covered by test |
| `v2` profile changes signature bytes | `v1` default retained and frozen; `v2` opt-in; default flip deferred to v4.0.0 |
