# v3.8.0 Implementation Plan — Audit Fixes

Source and full detail: [`SPEC-v3.8.0-audit-fixes.md`](../SPEC-v3.8.0-audit-fixes.md).
Ledger: [`tasks/v3.8.0-todo.md`](v3.8.0-todo.md).

The audit ran on `main` at `d47fa29` (v3.7.0). Every finding was confirmed by
reading the code and, where possible, running the built `dist/`. Tests are
green at baseline (103 files, 1990 tests, 47s).

## Method

1. **Characterize first.** For every bug, write the failing test (or extend an
   existing one) before the fix. This repo's suite is the proof that a fix
   works; a fix without a red-then-green test does not ship.
2. **One finding per commit.** Each item is independently reversible.
3. **Money and security before cosmetics.** Group A and B are the ones that
   lose money or leak data.
4. **Prefer fixes that delete code.** Group G removes more than it adds.
5. **Gate every phase** on the release gates below, not only at the end.

## Phase 1 — Money and cost correctness

### 1.1 Cost-alert denominator (A1)

- Add one percent helper; use it in `check()` and `_currentPercent()` in
  `src/cost/alerts.ts`.
- **Test:** `tests/cost/alerts.test.ts` with active reservations.
- **Accept:** percent matches the tracker's `committed/sessionBudget`.

### 1.2 Webhook alert delivery (A2)

- Mark fired only after a successful dispatch; add an `onDispatchError` hook;
  guard against double-fire while in flight.
- **Test:** new `tests/cost/alert-dispatch.test.ts`.
- **Accept:** a failed webhook does not mark the threshold fired.

### 1.3 Provider `finish` and usage chunks (A3)

- Emit `finish` on `message_stop` / last candidate / `done:true` in
  anthropic, google-genai, google-vertex, groq, ollama; map native usage in
  genai/vertex/ollama; accumulate Anthropic usage across `message_start` +
  `message_delta`.
- **Test:** per-adapter finish + usage assertions; correct the masking test.
- **Accept:** structured streaming finalizes on all five; prompt tokens are
  non-zero when billed.

### 1.4 Router cost weighting (A4, A5, F1b)

- Unknown price scores worst; un-clamp or rescale `finalScore`; hoist the
  `PRICING` table; fix `plan()` fallback cost/reasons.
- **Test:** `tests/router.test.ts` — cost order changes the winner; fallback
  cost is non-zero.
- **Accept:** a cost-weighted task picks the cheapest capable model.

**Verify:** `npx vitest run tests/cost/ tests/router.test.ts`

## Phase 2 — Security and data safety

### 2.1 Audit redaction (B1, H3, H4)

- `redactDeep` over `meta`/`previousValue`/`newValue`/`error`; pass through
  non-plain objects in `cloneValue` and drop cycle-back-references;
  seed `countByCategory` with all categories.
- **Test:** `tests/security-hardening.test.ts`.
- **Accept:** no key-shaped string, and no corrupted `Date`/`Map`, reaches the
  sink; every category key exists.

### 2.2 Injection guard (B2, B3)

- Replace every occurrence in strip mode; preserve non-text content parts.
- **Test:** `tests/prompt-injection-guard.test.ts` (repeat + multimodal).
- **Accept:** no residual payload; multimodal messages keep their parts.

### 2.3 Structured validation (B4)

- Reject non-object data for `type:"object"`.
- **Test:** `tests/schema-helpers.test.ts`.
- **Accept:** malformed output triggers repair.

### 2.4 Config snapshot (B5)

- Guard `providers`; redact `AlertChannel.url`; omit URL values in diagnostics.
- **Test:** `tests/config/`.
- **Accept:** no throw on malformed config; no credential-bearing URL in the
  snapshot.

**Verify:** `npx vitest run tests/security/ tests/security-hardening.test.ts tests/config/ tests/output/`
